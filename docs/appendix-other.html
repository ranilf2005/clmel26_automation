Idempotency: the pipeline stays green even when nothing needs to change.

Pipeline still works when the loopback already exists

If the loopback interfaces are already configured on the routers, the pipeline still succeeds. The deploy script checks the current state before making any change, so re-running the pipeline is safe and repeatable.

flowchart LR
    A["deploy_loopback runs"] --> B{"has_ip()?
Loopback300 = 2.2.2.2"}
    B -- "already present" --> C["Skip — no change"]
    B -- "missing" --> D["configure + write memory"]
    C --> E["Job SUCCESS"]
    D --> F{"verify"}
    F -- "ok" --> E
    F -- "fail" --> G["Job FAILED (exit 1)"]

How the check works

Before configuring an interface, configure_loopback.py calls has_ip(), which inspects show ip interface brief for both the interface name and the IP address:

excerpt — configure_loopback.py
def has_ip(dev, iface, ip):
    out = dev.execute("show ip interface brief")
    return (iface in out) and (ip in out)

# ...
if has_ip(dev, name, ip):
    print(f"[OK] {dev_name}: {name} already has {ip} - skipping")
    continue

Why this matters

Idempotency is a core NetDevOps principle: applying the same desired state repeatedly must produce the same result without side effects. This makes pipelines safe to re-run and easy to reason about.
