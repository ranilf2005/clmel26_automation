About this lab

In this lab, you manage abstracted network configurations in YAML format using a version control system hosted in GitLab. You use a testing lab to stage your configuration changes and run test cases.

When those test cases are successful, you (optionally) merge that configuration into your main configuration and deploy it to production.

Lab goals

⚑

Automate network tests

Write and run pyATS tests that verify reachability and routing on live CML devices.

↻

Integrate into CI/CD

Wire those tests into a GitLab CI/CD pipeline that runs automatically on every push.

▧

Deploy only when green

Configure loopback interfaces only when all tests pass.

▣

See results in GitLab

View clear pass / fail output directly in the GitLab pipeline view.

The end-to-end flow

  1. Commit configuration intent

    Describe the desired loopbacks in configs/loopbacks.yaml and commit to Git.

  2. Pipeline runs tests

    GitLab Runner executes the pyATS smoke job against the CML testbed.

  3. Gate on results

    If any test fails the pipeline stops; if all pass, the deploy stage runs.

  4. Apply & verify

    configure_loopback.py applies Loopback300 and verifies it on each router.
